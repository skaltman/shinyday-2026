Advice for working with LLMs

  • Use the best models
  • Have a human review the work
  • Be (a little) afraid

6 months ago we might have said, “use the best model available” now it’s more like use the least expensive model that does a sufficient job at your task, and switch depending on the task.

We’ll come back to this advice at the end of the talk.

Data analysis depends on context that is not in the data.

Definitions, conventions, documentation, and tacit organizational knowledge don’t automatically become available to an LLM just because it is more capable.

That context might live in data dictionaries, semantic views, or in the mind of a coworker who has been at the organization for 20 years.

Depending on your organization’s setup, making that context available can be a lot of work in itself.

Design the harness with correctness in mind

  • Prompting: prioritize correctness, not progress.
  • Tools that serve correctness: run code, see your session.
  • Access to your files and environment to have enough context.

Prompting: prioritize correctness over just moving the analysis forward. Posit Assistant … ” openness to uncertainty and subtlety, and a commitment to statistical rigor … Rather than maintaining a feeling of “moving forward,” call out ambiguities and unclear results.”” Tools: the ability to run code and see your session. Context: give it broad access to your files and environment, so it has a good chance at knowing the correct context to solve the problem.

The harness has to work well with the person, giving them the right amount of information at the right times.

We can’t just rely on individual oversight.

The system has to work with how people actually behave, not depend on individual willpower to review every action carefully. Three examples: auto mode, showing code, and slowing down EDA.

Auto mode and human review

The Simpsons GIF, via Caps N Lock

Repeated permission prompts can turn human review into rubber-stamping. The drinking bird is the joke: an approval click isn’t necessarily review.

Auto mode and human review

Anthropic, Auto mode is now the default in Claude Code (August 7, 2026)

Anthropic made auto mode the default for Pro, Max, and Team plans. In their controlled study with 1,053 paid professional testers, human reviewers blocked 13.6% of dangerous commands and auto mode blocked 89%. One permission prompt per session was replaced with dangerous command text; approving it didn’t execute anything dangerous. This was a test environment, not the testers’ own projects, and isn’t a claim that automation is always safer.

The point is to design review around actual human behavior, not assume that putting a person at every approval step automatically makes a system safer. PLACEHOLDER: Posit Assistant auto-mode comparison, if needed; not researched further.

Code visibility

Code should remain available for inspection, but users don’t need every execution block expanded all the time. Visibility is an interaction-design choice, not a substitute for reproducibility.

Databot originally put executed R/Python code and output directly in chat. Over time we added collapsible blocks and show/hide controls. In April 2026, Hide code became independent of result visibility: users could collapse the code input while leaving results visible.

Ordinary chat still shows data-analysis code by default. Optional hiding, collapsed Bash calls, and Canvas summaries are distinct behaviors, not a blanket switch to hiding R/Python code.

Trusted code

This vetted code used by the data scientists is what we’ll called trusted code they rely on it and trust it to give them the right answers

They also might have trusted code in

  • Shiny apps
  • R and Python packages
  • Quarto documents

Instead of the model writing code afresh every time it’s answering a question, what if it could discover and use this trusted code?

This is one of the core ideas behind a new open source package that we’re excited to share with you all today. It’s called commons.

https://pos.it/commons

commons helps data scientists build trustworthy data agents for their collaborators.

It’s an open source R and Python package built on ellmer / chatlas and shinychat. You can use it with whatever model from whatever provider you want.

Commons records which tools produced the answer. Trust is based on that execution path, not on the model’s confidence in its own answer. trust is deterministic

The citation itself is checked against trusted context. A custom answer is not promoted merely because the model says it used a trusted source.

commons does 3 things

  • Extract trusted calculations from existing artifacts into a data structure
  • A harness to give the right context at the right time
  • A feedback loop to push more queries up the trust ladder over time
